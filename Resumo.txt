- Escrevendo no console

    O comando console.log() é uma função do JavaScript usada para exibir informações no console do navegador, sendo muito útil para depuração e acompanhamento da execução do código.

    Exemplo:

    console.log("Olá mundo");

    Para contatenar informações utilizamos a virgula "," ou o simbolo de soma "+".

    A "," aplica um espaço entre as informações ja o "+" não aplica, sendo necessario aplicar um espaço manualmente entre as informações.

    Exemplo:

    console.log("Olá", "mundo");

    console.log("Olá" + " " + "mundo");

    Utilizada para criar campos de texto chamdos "strings", por padrão é utilizada a aspas duplas cercando o texto conforme exemplo abaixo:

    O ponto e vírgula indica o fim de uma instrução, exmeplo:

- Palavras reservadas

    São palavras que pertencem à linguagem, elas possuem significado próprio e não podem ser usadas como identificadores de nenhum tipo, por exemplo as palavras abaixo:

    if
    new
    let

- Variaveis e constantes

    Uma variável é um espaço na memória utilizado para armazenar um valor.

    Declaração

        let - Forma moderna e recomendada quando o valor pode mudar, pode ser declarada vazia.
        const - Usada quando o valor não pode mudar (tipos comuns), obrigatoriamente tem de ser atribuido um valor ao ser declarada

    Convenção de nomes

        Não pode começar com número
        Não pode conter espaços
        Não pode usar palavras reservadas
        Pode usar letras, números, _ e $
        Usar padrão "camelCase", primeira palavra minúscula, próximas com inicial maiúscula.
        Constantes devem ter todas a letras em maiúsculo quando o valor é realmente fixo e imutável, algo que representa uma constante "global" ou  de configuração porem pode ser escita como variavel comum em casos comuns

    Observações importantes:

        const é a forma recomendada por padrão para declarar quaisquer tipo de variáveis atualmente
        const não torna o valor imutável para objetos / arrays, apenas impede a reatribuição da variável

    Exemplos:

        let idade = 20;
        const nome = "Fernando";
        const PI = 3.1415;

- Tipagem dinamica

    JavaScript é uma linguagem de tipagem dinâmica, ou seja:

    Você não define o tipo da variável
    O tipo é definido automaticamente pelo valor atribuído
    Uma variável pode mudar de tipo durante a execução

- Tipos de valores

    Os valores são divididos em duas grandes categorias: tipos primitivos e objetos.

    Tipos primitivos são valores simples, guardando apenas uma informação, por exemplo:

        const nome = "Maria";
        const idade = 25;

    Objetos armazenam coleções de dados e podem conter propriedades e métodos, guardando diversas informações, por exemplo:

        const pessoa = {
            nome: "Maria",
            idade: 25,
            falar() {
                console.log("Olá!");
            }
        };

- Tipos de dados

    number - Representa números inteiros e decimais
    string - Texto entre aspas simples, duplas ou crase
    boolean - Valores lógicos
    undefined - Variável declarada, mas sem valor atribuído
    null - Representa ausência intencional de valor
    symbol - Usado para criar identificadores únicos (mais avançado)
    bigint - Números inteiros muito grandes (com a letra "n" no final do numero)
    object - Usado para agrupar dados e funcionalidades em uma única estrutura, ele representa coleções de pares chave > valor

- Operadores

    Aritméticos

        Usados para realizar cálculos matemáticos:

        +  adição
        -  subtração
        *  multiplicação
        /  divisão
        %  resto da divisão (módulo)
        ** exponenciação

    Atribuição

        Usados para atribuir valores a variáveis:

        =   atribuição simples
        +=  soma e atribui
        -=  subtrai e atribui
        *=  multiplica e atribui
        /=  divide e atribui
        %=  módulo e atribui
        **= exponencia e atribui

    Incrementais / Decrementais

        Servem para aumentar ou diminuir valores em 1:

        ++ incremento
        -- decremento

        Temos pré-incremento / pré-decremento:

        let i = 5;
        ++i; // i = 6

        Temos pós-incremento / pós-decremento:

        let j = 5;
        j++; // j = 6 (mas retorna 5 antes de incrementar)

        Diferença importante:

        pré: altera antes de usar
        pós: usa o valor e depois altera

    Comparadores

        Usados para comparar valores. Sempre retornam true ou false.

        ==  igual (com conversão de tipo)
        === igual estrito (sem conversão)
        !=  diferente
        !== diferente estrito
        >   maior
        <   menor
        >=  maior ou igual
        <=  menor ou igual

- Ordem dos Operadores

    A ordem define quais operações são executadas primeiro.

    Ordem simplificada (do maior para o menor):

    ()             parênteses
    **             exponenciação
    ++ --          incremento / decremento
    * / %          multiplicação, divisão, módulo
    + -            adição e subtração  
    < <= > >=      comparações
    == != === !==  igualdade
    && AND         lógico
    || OR          lógico
    = += -= *= ... atribuição

- Template literals

    Template literals são uma forma mais moderna e poderosa de trabalhar com strings no JavaScript. Eles foram introduzidos no ES6 e usam crases (`) em vez de aspas simples ou duplas.

    Principais características

    Interpolação de variáveis: Com template literals, você pode inserir variáveis e expressões diretamente dentro da string usando ${ }.

    Exemplo:

    const nome = "Fernando";
    const idade = 17;
    const mensagem = `Meu nome é ${nome} e tenho ${idade} anos.`;

    Sem template literals, seria necessário concatenar com +, o que fica menos legível.

    Expressões dentro da string: Não é só variável que funciona. Qualquer expressão JavaScript pode ser usada.

    Exemplo:

    const a = 10;
    const b = 5;
    const resultado = `A soma é ${a + b}`;

    Strings multilinha: Template literals permitem quebrar linhas sem usar \n.

    Exemplo:

    const texto = `Linha 1
    Linha 2
    Linha 3`;

- Estruturas de decisão

    As estruturas de decisão permitem que o código escolha caminhos diferentes com base em condições (verdadeiro ou falso).

    if

        O if executa um bloco de código somente se a condição for verdadeira.

        Exemplo:
        let idade = 18;
        if (idade >= 18) {
            console.log("Maior de idade");
        }

        Se a condição for falsa, o código dentro do if simplesmente não é executado.

    if else

        O if else permite definir o que acontece quando a condição é verdadeira e o que acontece quando é falsa.

        Exemplo:
        let idade = 16;
        if (idade >= 18) {
            console.log("Maior de idade");
        } else {
            console.log("Menor de idade");
        }

        Aqui sempre um dos dois blocos será executado.

    if else if

        Usado quando há várias condições possíveis. O JavaScript testa as condições em ordem, e executa o primeiro bloco verdadeiro.

        Exemplo:
        let nota = 7;
        if (nota >= 9) {
            console.log("Excelente");
        } else if (nota >= 7) {
            console.log("Aprovado");
        } else if (nota >= 5) {
            console.log("Recuperação");
        } else {
            console.log("Reprovado");
        }

    switch

        Usada quando você precisa comparar o valor de uma variável (ou expressão) com vários valores possíveis. Ele costuma ser uma alternativa mais organizada ao uso de vários if / else if.

        O switch avalia uma expressão uma única vez e compara o resultado com cada case. Quando encontra um case correspondente, executa o código daquele bloco.

        Sintaxe básica:

        switch (expressao) {
            case valor1:
                // código se expressao === valor1
                break;
            case valor2:
                // código se expressao === valor2
                break;
            default:
                // código se nenhum case for atendido
        }

        Exemplo:
        let dia = 3;
        switch (dia) {
            case 1:
                console.log("Domingo");
                break;
            case 2:
                console.log("Segunda");
                break;
            case 3:
                console.log("Terça");
                break;
            default:
                console.log("Dia inválido");
        }

        Informações importantes:

        break: o break é essencial na maioria dos casos. Sem ele, o JavaScript continua executando os próximos cases, mesmo que eles não correspondam.

        default: o default funciona como o else final. Ele é executado quando nenhum case corresponde ao valor testado.

        Comparação usada no switch: switch usa comparação estrita (===). Isso significa que tipo e valor precisam ser iguais.

    Operador ternário "?"

        É um operador condicional que funciona como uma forma curta do if/else. Ele é chamado de ternário porque trabalha com três partes.

        Sintaxe:

        condicao ? valorSeVerdadeiro : valorSeFalso

        Se a condição for verdadeira, o operador retorna o primeiro valor. Se for falsa, retorna o segundo.

        Exemplo:

        let idade = 20;
        let resultado = idade >= 18 ? "Maior de idade" : "Menor de idade";

- Conversão de Tipos (explicita)

    Conversão de tipos acontece quando você força explicitamente um valor de um tipo a virar outro tipo. É previsível e controlada.

    Conversão para Number

    Formas comuns:

    Number(valor) - Converte para número ou retorna NaN se não for possível.
    Exemplo:
    Number("10") // 10

    parseInt(valor) - Converte para inteiro e ignora o resto após encontrar algo inválido.
    Exemplo:
    parseInt("10.9") // 10

    parseFloat(valor) - Converte para número decimal.
    Exemplo:
    parseFloat("10.5") // 10.5

    Conversão para String

    Formas comuns:

    String(valor)
    Exemplos:
    String(123) // "123"

    valor.toString()
    Exemplos:
    (123).toString() // "123"

    Conversão para Boolean

    Existe somente uma forma:

    Boolean(valor)
    Exemplos:
    Boolean(0) // false
    Boolean("0") // true

    Valores convertidos para false:

    false
    0
    -0
    0n
    ""
    null
    undefined
    NaN

    Todos os outros valores são true.

- Coerção de Tipos (implicita)

    Coerção ocorre quando o JavaScript converte tipos automaticamente durante operações.

    Coerção com operador +

    O operador + é especial, se algum operando for string faz concatenação, caso contrário é feita soma numérica.

    Exemplos:
    "5" + 2 // "52"
    2 + "5" // "25"
    "5" + true // "5true"
    "5" + null // "5null"
    2 + 2 + "5" // "45"
    "5" + 2 + 2 // "522"

    A ordem importa muito, a mesma é feita da esquerda para a direita.

    Coerção com operadores matemáticos (-, *, /, %)

    Esses operadores sempre tentam converter para Number.

    Exemplos:
    "5" - 2 // 3
    "5" * "2" // 10
    "10" / "2" // 5
    "5" % 2 // 1

- Valores "truthy" e "falsy"

    Qualquer valor pode ser interpretado como verdadeiro (true) ou falso (false) quando usado em contextos lógicos, como if, while, operadores lógicos (&&, ||, !) etc. Esses valores são chamados de "truthy" e "falsy".

    Valores "falsy"

        Falsy são os valores que, quando convertidos para boolean, resultam em false.

        Em JavaScript, existem apenas 7 valores "falsy":

        false
        0
        -0
        0n        (BigInt zero)
        "" ou ''  (string vazia)
        null
        undefined
        NaN

        Exemplos:
        if (false) { }        // não executa
        if (0) { }            // não executa
        if ("") { }           // não executa
        if (null) { }         // não executa
        if (NaN) { }          // não executa

        Qualquer um desses valores dentro de um if será tratado como false.

    Valores "truthy"

        Truthy são todos os outros valores que não estão na lista de falsy. Ou seja, se não é falsy, é truthy.

        Exemplos comuns de valores truthy:

        true
        1
        -1
        "0"
        "false"
        " "        (string com espaço)
        []         (array vazio)
        {}         (objeto vazio)
        function() {}

        Exemplos:
        if (true) { }         // executa
        if (1) { }            // executa
        if ("0") { }          // executa
        if ([]) { }           // executa
        if ({}) { }           // executa

- Operadores de igualdade

    Operadores de igualdade servem para comparar valores. O ponto mais importante é entender a diferença entre comparar "só o valor" e comparar "valor + tipo".

    Operador == (igualdade solta)

        O == compara apenas o valor, não o tipo. Se os tipos forem diferentes, o JavaScript tenta converter (coerção de tipo) antes de comparar.

        Exemplos:
        5 == 5            > true
        5 == "5"          > true
        0 == false        > true
        null == undefined > true

        Isso acontece porque o JavaScript converte os valores para tentar deixá-los do mesmo tipo antes da comparação.

        Esse comportamento pode causar confusão e erros difíceis de perceber.

    Operador === (igualdade estrita)

        O === compara o valor e o tipo ao mesmo tempo. Não existe conversão de tipos.

        Exemplos:
        5 === 5            > true
        5 === "5"          > false
        0 === false        > false
        null === undefined > false

        Esse é o operador recomendado na maioria dos casos, porque o resultado é previsível.

    Operador != (diferença solta)

        O != é o oposto do ==. Ele verifica se os valores são diferentes, permitindo coerção de tipo.

        Exemplos:
        5 != 6        > true
        5 != "5"      > false
        0 != false    > false

        Assim como o ==, ele pode gerar resultados inesperados.

    Operador !== (diferença estrita)

        O !== é o oposto do ===. Ele verifica se o valor ou o tipo são diferentes, sem conversão.

        Exemplos:
        5 !== 6        > true
        5 !== "5"      > true
        0 !== false    > true

- Operadores logicos

    São usados para combinar ou inverter condições. Eles trabalham muito com valores booleanos, mas em JavaScript também retornam valores não booleanos, o que é algo importante de entender.

    Principais: &&, || e !

    Operador && (E lógico)

    O && retorna verdadeiro se todas as condições forem verdadeiras.

    Exemplo básico:
    true && true   > true
    true && false  > false

    Operador || (OU lógico)

    O || retorna verdadeiro se pelo menos uma condição for verdadeira.

    Exemplo básico:
    true || false   > true
    false || false  > false

    Operador ! (NÃO lógico)

    O ! inverte o valor lógico.

    Exemplos:
    !true   > false
    !false  > true

- Declarações e expressões

    São dois conceitos fundamentais que definem como o código é escrito e executado. A diferença principal é que expressões produzem um valor, enquanto declarações executam uma ação.

    Declarações (statements)

        Declarações são instruções completas que dizem ao JavaScript para fazer algo. Elas não retornam um valor que possa ser usado diretamente.

        Exemplos:

        Declaração de variável
        let idade = 18;

        Declarações de controle de fluxo
        if (idade >= 18) {
            console.log("Maior de idade");
        }

        Observação: Você não pode usar uma declaração onde o JavaScript espera um valor.

    Expressões (expressions)

        Expressões são trechos de código que sempre resultam em um valor. Esse valor pode ser usado, atribuído a uma variável, passado como parâmetro, etc.

        Exemplos:

        Expressões literais
        10
        "texto"

        Expressões aritméticas
        5 + 3
        10 * 2

        Expressões de comparação
        idade >= 18
        a === b

        Expressões de atribuição
        x = 10
        y += 2

        Expressões lógicas
        a && b
        a || b

- Strict mode

    É um modo especial de execução que torna a linguagem mais rígida e segura, ajudando a evitar erros comuns e más práticas.

    Ele foi criado para:

    Evitar bugs silenciosos
    Impedir comportamentos perigosos
    Forçar um código mais previsível

    Você ativa o strict mode usando a string abaixo. Ela deve ser usada no topo do arquivo javascript:

    "use strict";

    O que o strict mode muda na prática

    Proíbe variáveis não declaradas
    Impede duplicação de parâmetros
    Proíbe apagar variáveis, funções ou parâmetros
    Impede o uso de palavras reservadas futuras
    Corrige erros silenciosos
    Algumas operações que antes falhavam silenciosamente passam a gerar erro

- Funções

    São blocos de código reutilizáveis que servem para executar uma tarefa ou calcular e retornar um valor. Elas são um dos conceitos mais importantes da linguagem.

    Em vez de repetir o mesmo código várias vezes, você coloca esse código dentro de uma função e a reutiliza sempre que precisar.

    Uma função é um conjunto de instruções que:

        Pode receber dados de entrada (parâmetros)
        Executa um bloco de código
        Pode ou não retornar um valor

    Exemplo simples de ideia:

        Some dois números > isso vira uma função.

    Temos basicamente 3 formatos de declaração de funções:

        Função tradicional (Function Declaration)
        Expressão de função (Function Expression)
        Função seta (Arrow function)

    Diferença nos 3 formatos de declaração de funções:

        Função tradicional (Function Declaration):

            Possui um nome obrigatório.
            Pode ser chamada antes de ser declarada (hoisting).
            Ideal para funções principais do programa.

        Expressão de função (Function Expression):

            Armazenada em variável.
            Passada para outra função.
            Retornada por outra função.
            Não pode ser chamada antes de ser declarada (hoisting).
            Muito comum quando a função será usada como um valor.

        Função seta (Arrow function):

            É uma forma mais curta de escrever funções.
            A grande diferença é o "this".
            A Arrow Function não cria seu próprio this. Ela usa o this do contexto onde foi criada (escopo léxico). Por isso, não é indicada para métodos de objetos.

    Vantagens e desvantagens

        Function Declaration
            Vantagens: Pode ser chamada antes da declaração (hoisting), ótima para funções principais
            Desvantagens: Sintaxe mais longa

        Function Expression
            Vantagens: Trata a função como um valor, ótima para callbacks e atribuições
            Desvantagens: Não possui hoisting

        Arrow Function
            Vantagens: Sintaxe curta, muito usada com map, filter, reduce e callbacks
            Desvantagens: Não possui this próprio e não deve ser usada como método de objeto

    Função tradicional (Function Declaration)

        A função é declarada de forma separada, com nome, e chamada quando necessária.

        Declaração:

            function <nome da função>(<parametro 1>, <parametro 2>, <demais parametros...>) {
                <codigo da função>
                return <valor a ser retornado pela função>
            }

        Chamada:

            <nome da funcao>(<parametro 1>, <parametro 2>, <demais parametros...>);

        Exemplos:

            function logger() {
                console.log("Teste");
            }

            function idade(anoAtual, anoNascimento) {
                let idade = anoAtual - anoNascimento;
                return idade;
            }

            logger();

            idade(2025, 1979);

    Expressão de função (Function Expression)

        A função é declarada sem nome e atribuida a uma variavel, para ser usada é necessario declarar esta variavel.

        Declaração:

            const <nome da variavel> = function(<parametro 1>, <parametro 2>, <demais parametros...>) {
                <codigo da função>
                return <valor a ser retornado pela função>
            }

        Chamada:

            <nome da variavel>(<parametro 1>, <parametro 2>, <demais parametros...>);

        Exemplos:

            const logger = function() {
                console.log("Teste");
            }

            const idade = function(anoAtual, anoNascimento) {
                let idade = anoAtual - anoNascimento;
                return idade;
            }

            logger();

            idade(2025, 1979);

    Função seta (Arrow function)

        A função é declarada sem nome e atribuida a uma variavel, para ser usada é necessario declarar esta variavel. Porem é uma forma mais curta e moderna de escrever funções pois não leva a palavra function.

        Declaração:

            const <nome da variavel> = (<parametro 1>, <parametro 2>, <demais parametros...>) => {
                <codigo da função>
                return <valor a ser retornado pela função>
            }

        Chamada:

            <nome da variavel>(<parametro 1>, <parametro 2>, <demais parametros...>);

        Exemplos:

            const logger = () => {
                console.log("Teste");
            }

            const idade = (anoAtual, anoNascimento) => {
                let idade = anoAtual - anoNascimento;
                return idade;
            }

            logger();

            idade(2025, 1979);

- Arrays

    São estruturas de dados usadas para armazenar vários valores em uma única variável, organizados por índice numérico. Eles são fundamentais para trabalhar com listas de dados.

    Características importantes

        Cada elemento tem um índice (posição)
        O índice começa em 0
        Pode armazenar qualquer tipo de dado
        Pode misturar tipos diferentes (número, string, objeto, função, etc.)
        O tamanho pode mudar dinamicamente

    Declaração

        Forma literal (mais comum)

            // Vazio
            let <nome do array> = [];

            // Com itens
            let <nome do array> = [<item>, <item>, ...];

            Exemplos:

            let frutas = [];
            let frutas = ["maçã", "banana", "laranja"];

            É a forma recomendada por ser mais simples e clara.

        Usando o construtor Array

            // Vazio
            let <nome do array> = new Array();

            // Com itens
            let <nome do array> = new Array(<item>, <item>, ...);

            Exemplos:

            let frutas = new Array();
            let frutas = new Array("maçã", "banana", "laranja");

            Funciona, mas é menos usada.

    Arrays podem misturar tipos

        let dados = [1, "texto", true, { nome: "Ana" }, function() {}];

        Isso é permitido em JavaScript.

     Tamanho do array (length)

        A propriedade length indica o número de elementos.

        cores.length; // 3

        Importante, length não é método, é propriedade.

    Acessando elementos do array

        let cores = ["azul", "verde", "vermelho", "amarelo"];

    Mostrar todos

        Não colocar nenhum indice dentro do colchetes:

        cores[]; // "azul", "verde", "vermelho", "amarelo"

    Primeiro elemento do array

        É sempre o item na posição zero "0":

        cores[0]; // "azul"

    Elementos em posição especifica

        Use o índice desejado entre colchetes:

        cores[1]; // "verde"
        cores[2]; // "vermelho"

    Ultimo elemento do array

        Usar a propriedade length e subtrair 1.

        cores.length - 1

        Exemplo:

        cores[cores.length - 1]; // "amarelo"

    Adicionar elementos (operações comuns)

        Ao inserir um item seu metodo retorno o novo tamanho do array (caso necessario utilziarmos).

        let numeros = [1, 2];

        Adicionar no início (unshift):

        numeros.unshift(0);
        // [0, 1, 2]

        Adicionar em local especifico (splice):

        array.splice(<indice>, <qtde de itens a remover>, <item a ser inserido>);

        Exemplo:

        let frutas = ["maçã", "banana", "laranja"];
        frutas.splice(1, 0, "uva");

        Resultado:
        // ["maçã", "uva", "banana", "laranja"]

        Adicionar no final (push):

        numeros.push(3);
        // [0, 1, 2, 3]

    Remover elementos

        Ao remover um elemento seu metodo retorna o item removido (caso necessario utilizarmos).

        Remover do início (shift):

        numeros.shift();
        // remove o primeiro

        Remover em local especifico (splice):

        array.splice(<indice a ser removido>, 1);

        Exemplo:

        let frutas = ["maçã", "banana", "laranja"];
        frutas.splice(1, 1);

        Resultado:
        // ["maçã", "laranja"]

        Remover do final (pop):

        numeros.pop();
        // remove o último     

    Buscar elementos

        Verificar se existe (includes):

        numeros.includes(2); // true

        Encontrar índice (indexOf):

        numeros.indexOf(2); // retorna o índice ou -1

- Objetos

    São estruturas de dados usadas para representar entidades do mundo real, agrupando propriedades (dados) e comportamentos (funções) em um único lugar.

    Um objeto é uma coleção de pares "chave : valor".

    A chave (propriedade) é uma string
    O valor pode ser qualquer tipo de dado: número, string, boolean, array, função, outro objeto etc.

    Exemplo:

    let pessoa = {
        nome: "Ana",
        idade: 25,
        ativo: true
    };

    Diferença entre objetos e arrays

        Array:

        Usado para listas ordenadas
        Acesso por índice numérico
        Ordem importa

        Exemplo:

        let numeros = [10, 20, 30];

        Objeto:

        Usado para representar coisas com atributos
        Acesso por nome da propriedade
        Ordem não é o foco

        Exemplo:

        let pessoa = { 
            nome: "Ana", 
            idade: 25 
        };

    Declarando objetos

        Forma literal (mais comum)

        let carro = {
            marca: "Ford",
            modelo: "Fiesta",
            ano: 2018
        };

        Objeto vazio e adicionar propriedades depois

        let usuario = {};
        usuario.nome = "Carlos";
        usuario.idade = 30;

        Usando new Object (pouco usado) e adicionar propriedades depois

        let produto = new Object();
        produto.nome = "Teclado";

        A forma literal {} é a recomendada.

    Acessando propriedades

        Notação com ponto (.)

        Usada quando o nome da propriedade é conhecido e válido.

        pessoa.nome;
        pessoa.idade;

        Exemplo:
        console.log(pessoa.nome);

        Notação com colchetes []

        Usada quando:

        O nome da propriedade está em uma variável
        A propriedade tem espaços ou caracteres especiais

        Exemplo:

        let prop = "idade";
        pessoa[prop];

        Exemplo com nome inválido:

        let obj = {
        "nome completo": "Ana Silva"
        };
        obj["nome completo"];

    Adicionando propriedades

        Com ponto:

        pessoa.altura = 1.70;

        Com colchetes:

        pessoa["peso"] = 65;

        Usando variável:

        let chave = "cidade";
        pessoa[chave] = "São Paulo";

    Função como propriedade (métodos)

        Quando uma função está dentro de um objeto, ela é chamada de método.

        Exemplo:

        let pessoa = {
            nome: "Ana",
            idade: 25,
            falar: function() {
                console.log("Olá, meu nome é " + this.nome);
            }
        };

        Chamando o método:

        pessoa.falar();

        Forma curta (mais moderna):

        let pessoa = {
            nome: "Ana",
            falar() {
                console.log("Olá, meu nome é " + this.nome);
            }
        };

    this

        this é uma palavra-chave que se refere ao objeto que está chamando a função.

        No exemplo:

        pessoa.falar();

        Dentro da função:
        this === pessoa

        Por isso:
        this.nome acessa pessoa.nome

        Exemplo:

        let carro = {
            marca: "Toyota",
            mostrarMarca() {
                console.log(this.marca);
            }
        };

        carro.mostrarMarca();

        Cuidado com arrow function e this, arrow functions não têm this próprio.

- Estruturas de repetição

    Servem para executar o mesmo bloco de código várias vezes, enquanto uma condição for atendida ou enquanto houver itens a percorrer.

    for

        O for é usado quando você sabe ou consegue prever quantas vezes o loop vai rodar.

        Estrutura:

        for (inicialização; condição; incremento) {
            // código executado a cada repetição
        }

        Exemplo:

        for (let i = 0; i < 5; i++) {
            console.log(i);
        }

        O que cada parte faz:

        inicialização > cria a variável de controle (let i = 0)
        condição > enquanto for true, o loop continua (i < 5)
        incremento > executado ao final de cada volta (i++)

        Uso comum:

        Percorrer arrays
        Contadores

    while

        O while é usado quando não se sabe exatamente quantas vezes o loop vai rodar, apenas a condição.

        Estrutura:

        while (condição) {
            // código executado a cada repetição
        }

        Exemplo:

        let i = 0;

        while (i < 5) {
            console.log(i);
            i++;
        }

        Se a condição começar falsa, o código nunca executa.

        Uso comum:

        Esperar um evento
        Ler dados até uma condição ser atendida

    do while

        O do while é parecido com o while, mas com uma diferença importante:

        Ele sempre executa pelo menos uma vez.

        Estrutura:

        do {
            // código executado a cada repetição
        } while (condição);

        Exemplo:

        let i = 10;

        do {
            console.log(i);
            i++;
        } while (i < 5);

        Mesmo com a condição falsa, o código roda uma vez.

    Diferença entre for, while e do while

        for:

        Ideal quando sabe o número de repetições
        Tudo fica em uma linha (controle claro)

        while:

        Testa a condição antes
        Pode não executar nenhuma vez

        do while:

        Testa a condição depois
        Executa pelo menos uma vez

    break

        O break interrompe completamente o loop, mesmo que a condição ainda seja verdadeira.

        Exemplo:

        for (let i = 0; i < 10; i++) {
            if (i === 5) {
                break;
            }
            console.log(i);
        }

        Resultado:
        0 1 2 3 4

        Uso comum:

        Parar quando encontrar um valor específico
        Evitar processamento desnecessário

    continue

        O continue pula a iteração atual e vai direto para a próxima.

        Exemplo:

        for (let i = 0; i < 5; i++) {
            if (i === 2) {
                continue;
            }
            console.log(i);
        }

        Resultado:
        0 1 3 4

        Uso comum:

        Ignorar certos valores
        Filtrar dentro do loop

    Comparação rápida entre break e continue

        break > sai do loop
        continue > pula a volta atual

- O que é HTML?

    HTML (HyperText Markup Language) é a linguagem usada para criar a estrutura de uma página da web, como títulos, textos, imagens, links e tabelas.

- O que é CSS?

    CSS (Cascading Style Sheets) é a linguagem usada para definir a aparência da página, como cores, fontes, tamanhos, margens e posicionamento dos elementos.

- O que é o arquivo index.html?

    É o arquivo principal de um site. Quando você acessa um endereço na web, normalmente o navegador procura primeiro pelo arquivo index.html.

- Como criar um arquivo básico HTML no VS Code?

    Abra o VS Code.
    Crie uma nova pasta para o projeto.
    Crie um arquivo chamado index.html.
    Digite ! e pressione Enter (ou Tab). O VS Code criará automaticamente a estrutura básica do HTML.

- Explicação básica de um arquivo HTML gerado pelo VS Code

    <!doctype html>
    <html lang="en">
        <head>
            <meta charset="UTF-8" />
            <meta name="viewport" content="width=device-width, initial-scale=1.0" />
            <title>Document</title>
        </head>
        <body></body>
    </html>

    <!doctype html> - Informa ao navegador que o documento usa HTML5.
    <html> - Contém todo o conteúdo da página.
    lang="en" - Define o idioma da página (neste caso, inglês).
    <head> - Contém informações da página que não aparecem no conteúdo, como título e configurações.
    <meta charset="UTF-8"> - Permite usar caracteres especiais, como ç e á.
    <meta name="viewport"...> - Faz a página se adaptar corretamente a celulares e tablets.
    <title> - Define o título exibido na aba do navegador.
    <body> - Contém todo o conteúdo visível da página, como textos, imagens e botões.

- O que é versao em documento HTML?

    Em HTML, a versão do documento indica qual padrão de HTML o navegador deve usar para interpretar a página.

    Hoje, praticamente todos os sites usam HTML5.

    Isso é informado logo na primeira linha do arquivo:

    <!doctype html>

    Essa linha diz ao navegador:

    "Este documento foi escrito usando o padrão HTML5."

    Por que isso é importante?

    Se essa declaração não existir ou estiver incorreta, o navegador pode entrar em um modo de compatibilidade ("Quirks Mode"), interpretando a página como se fosse uma versão muito antiga do HTML, o que pode causar problemas de layout e funcionamento.

- O que são elementos HTML?

    Elementos HTML são as partes que formam uma página, como títulos, parágrafos, imagens e links. Geralmente são compostos por uma tag de abertura, conteúdo e uma tag de fechamento.

    Exemplo:

    <p>Olá, mundo!</p>

- O que são tags HTML?

    Tags são os comandos usados para criar elementos HTML. Elas ficam entre os símbolos < e >.

    Exemplos:

    <h1>
    <p>
    <img>
    <a>

- O que são atributos HTML?

    Atributos fornecem informações extras para uma tag. Eles são escritos dentro da tag de abertura.

    Exemplo:

    <img src="foto.jpg" alt="Minha foto">
    src - Informa onde está a imagem.
    alt - Define um texto alternativo para a imagem.

- O que é aninhamento de elementos?

    Aninhamento é quando um elemento HTML é colocado dentro de outro elemento.

    Exemplo:

    <body>
        <h1>Meu Site</h1>
        <p>Bem-vindo!</p>
    </body>

    Nesse exemplo, as tags <h1> e <p> estão aninhadas dentro da tag <body>.

- O que é elemento pai e elemento filho?

    Quando um elemento está dentro de outro:

    Elemento pai - É o elemento que contém outro elemento.
    Elemento filho - É o elemento que está dentro do elemento pai.

    Exemplo:

    <body>
        <p>Olá, mundo!</p>
    </body>

    <body> - elemento pai.
    <p> - elemento filho.

- O que são "class" e "id"?

    São atributos HTML usados para identificar elementos.

    "class"

    Serve para identificar um ou vários elementos com o mesmo nome.

    Exemplo:

    <p class="texto">Primeiro parágrafo</p>
    <p class="texto">Segundo parágrafo</p>

    Ambos pertencem à classe texto.

    "id"

    Serve para identificar um único elemento da página.

    Exemplo:

    <h1 id="titulo">Meu Site</h1>

    O id="titulo" deve ser único na página.

- O que é DOM?

    DOM (Document Object Model) é a representação da página HTML em forma de árvore, criada pelo navegador.

    Ela permite que o JavaScript encontre, altere, adicione ou remova elementos da página.

    Exemplo:

    <body>
        <h1>Título</h1>
        <p>Texto</p>
    </body>

    O navegador transforma esse HTML em uma estrutura organizada (árvore), chamada DOM.

- O que é semântica em HTML?

    Semântica é usar a tag correta para cada tipo de conteúdo, tornando o código mais organizado, acessível e fácil de entender.

    Exemplos de tags semânticas:

    <header> - cabeçalho
    <nav> - menu de navegação
    <main> - conteúdo principal
    <section> - seção da página
    <article> - artigo ou conteúdo independente
    <footer> - rodapé

    Em vez de escrever tudo com <div>, usamos tags que descrevem o significado do conteúdo.

    Exemplo:

    <header>
        <h1>Meu Site</h1>
    </header>

    <main>
        <p>Bem-vindo ao site.</p>
    </main>

    <footer>
        <p>Todos os direitos reservados.</p>
    </footer>

        <h1> - título principal

        Campo numérico.

        <input type="date">

    Boas práticas:

- O que é CSS

- CSS Box Model

    O CSS Box Model (Modelo de Caixa) é um dos conceitos mais importantes do CSS. Ele define como o navegador calcula o tamanho e o espaço ocupado por cada elemento HTML.

    A ideia principal é que todo elemento HTML é tratado como uma caixa (box).

    Estrutura do Box Model

        Um elemento é composto por quatro partes:

        +-------------------------------------------+
        |                  Margin                   |
        |  +-------------------------------------+  |
        |  |               Border                |  |
        |  |  +-------------------------------+  |  |
        |  |  |            Padding            |  |  |
        |  |  |  +-------------------------+  |  |  |
        |  |  |  |         Content         |  |  |  |
        |  |  |  +-------------------------+  |  |  |
        |  |  +-------------------------------+  |  |
        |  +-------------------------------------+  |
        +-------------------------------------------+

        Da parte de dentro para fora:

        Content (Conteúdo): É onde ficam os dados do elemento
        Padding (Espaçamento interno): O padding é o espaço entre o conteúdo e a borda.
        Border (Borda): É a borda do elemento.
        Margin (Espaçamento externo): A margem fica do lado de fora.

    Como o navegador calcula o tamanho?

        Suponha:

        width: 300px;
        padding: 20px;
        border: 5px;

        Sem alterar box-sizing, o tamanho total será: Conteúdo = 300px

        Padding esquerdo = 20px
        Padding direito = 20px
        Border esquerda = 5px
        Border direita = 5px

        Total: 300 + 20 + 20 + 5 + 5 = 350px

        Ou seja: width total = 350px

    O problema do Box Model padrão

        Por padrão, o navegador usa:

        box-sizing: content-box;

        Isso significa que a propriedade width controla apenas a área do conteúdo.

        Exemplo:

        width: 300px;
        padding: 20px;
        border: 5px solid;

        Resultado: Tamanho total = 350px

        Isso pode dificultar o controle do layout.

    A solução

        box-sizing: border-box

        O navegador ajusta o conteúdo para que o tamanho total continue sendo 300px.

        300px (total)

        ┌─────────────────────────────┐
        │ Border                      │
        │ Padding                     │
        │ Conteúdo (reduzido)         │
        └─────────────────────────────┘

        Isso torna os layouts muito mais previsíveis, evita surpresas com o cálculo do tamanho dos elementos e facilita bastante a construção de layouts com CSS.

- Medidas em CSS

    São as unidades usadas para definir tamanhos, espaçamentos, posições e dimensões dos elementos.

    Existem dois grandes grupos:

    Medidas absolutas
    Medidas relativas

    Medidas Absolutas

        São unidades de tamanho fixo. Elas não mudam de acordo com a tela ou o tamanho da fonte.

        "px" (Pixels) é a unidade mais utilizada.

        Quando usar?

        Bordas
        Ícones
        Pequenos espaçamentos
        Elementos que precisam de tamanho fixo

        Na prática, para páginas web, quase sempre usa-se "px".

    Medidas Relativas

        São calculadas com base em outro valor, como o tamanho da fonte, do elemento pai ou da janela do navegador.

        São as mais indicadas para criar layouts responsivos.

        "%" a porcentagem depende do elemento pai.

        "em" é baseado no tamanho da fonte do elemento pai (atenção ao efeito cascata pois ele multiplica sobre o valor herdado).

        "rem" significa "Root EM", ele sempre usa o tamanho da fonte do elemento <html>.

        "auto" permite que o navegador calcule o valor automaticamente (muito usado para centralizar elementos)

        Por que usar "rem"?

            Ele facilita a acessibilidade. Se o usuário aumentar o tamanho padrão da fonte no navegador, todos os elementos definidos em "rem" aumentam proporcionalmente.

        Comparação das principais unidades

            | Unidade | Base de cálculo           | Uso recomendado                                        |
            | ------- | ------------------------- | ------------------------------------------------------ |
            | "px"    | Valor fixo                | Bordas, ícones, detalhes                               |
            | "%"     | Elemento pai              | Largura e altura relativas                             |
            | "em"    | Fonte do elemento pai     | Espaçamentos e componentes, com cuidado ao aninhamento |
            | "rem"   | Fonte do <html>           | Tamanho de texto e espaçamentos (muito recomendado)    |

        Recomendações para iniciantes

            Use "px" para bordas, sombras e pequenos detalhes visuais.
            Prefira "rem" para tamanhos de fonte, margens e padding, pois melhora a consistência e a acessibilidade.
            Use "%" para elementos que devem acompanhar o tamanho do elemento pai.

- Javascript como selecionar elementos no HTML

    Uma das tarefas mais comuns em JavaScript é selecionar elementos da página HTML para poder ler informações, alterar conteúdo, modificar estilos ou responder a eventos.

    O JavaScript faz isso através do DOM (Document Object Model).

    Métodos mais utilizados

        Hoje, os métodos mais usados são:

        | Método                              | Retorna                     
        | ----------------------------------- | ----------------------------
        | document.querySelector()            | Primeiro elemento encontrado
        | document.querySelectorAll()         | Lista de elementos          
        | document.getElementById()           | Elemento pelo id            
        | document.getElementsByClassName()   | Coleção de elementos        
        | document.getElementsByTagName()     | Coleção de elementos        
        | document.getElementsByName()        | Coleção de elementos        

        Os três primeiros são os que você usará na maior parte do tempo.

    Selecionar pelo ID (getElementById)

        Como o id deve ser único na página esse método retorna apenas um elemento.

        Exemplo:

        const titulo = document.getElementById("titulo");

    Selecionar pela Classe (getElementsByClassName)

        Como uma classe pode ser usada em diversos elementos esse método retorna uma HTMLCollection.

        Exemplo:

        const textos = document.getElementsByClassName("texto");

    Selecionar pela Tag (getElementsByTagName)

        Como podem existir diversos elementos esse método retorna uma HTMLCollection.

        Exemplo:

        const paragrafos = document.getElementsByTagName("p");

    Seletor diversificado (querySelector)

        Esse método retorna apenas um elemento, o primeiro encontrado.

        É o método mais utilizado atualmente, ele aceita qualquer seletor.

        # para id
        . para classe
        propria tag para tag

        Exemplo:

        const titulo = document.querySelector("#titulo");
        const texto = document.querySelector(".texto");
        const h1 = document.querySelector("h1");

    Seletor diversificado (querySelectorAll)

        Esse método retorna uma NodeList pois pode encontrar diversos elementos.

        Ele aceita qualquer seletor.

        # para id
        . para classe
        propria tag para tag

        Exemplo:

        const titulo = document.querySelectorAll("#titulo");
        const texto = document.querySelectorAll(".texto");
        const h1 = document.querySelectorAll("h1");

    Qual método usar?

        Na maioria dos projetos modernos:

        Use "document.querySelector()" quando precisar de um único elemento.
        Use "document.querySelectorAll()" quando precisar de vários elementos.

- O que é uma NodeList e uma HTMLCollection

    Quando você seleciona vários elementos do HTML, o JavaScript não retorna um array comum. Em vez disso, ele retorna um objeto especial, que pode ser uma NodeList ou uma HTMLCollection, dependendo do método utilizado.

    Embora pareçam arrays, eles têm diferenças importantes.

    O que é uma NodeList?

        Uma NodeList é uma coleção (lista) de nós do DOM.

        Normalmente, você a obtém com:

        document.querySelectorAll();

        Exemplo:

        <p>Primeiro</p>
        <p>Segundo</p>
        <p>Terceiro</p>
        const paragrafos = document.querySelectorAll("p");
        console.log(paragrafos);

        Resultado:

        NodeList(3)

        Ela contém os três elementos <p>.

        Acessando elementos:

        console.log(paragrafos[0]);
        console.log(paragrafos[1]);
        console.log(paragrafos[2]);

        Resultado:

        <p>Primeiro</p>
        <p>Segundo</p>
        <p>Terceiro</p>

        Percorrendo uma NodeList:

        Uma grande vantagem é que ela possui o método forEach().

        paragrafos.forEach(function (p) {
            console.log(p);
        });

    O que é uma HTMLCollection?

        Uma HTMLCollection é uma coleção de elementos HTML.

        Ela é retornada por métodos como:

        document.getElementsByClassName();
        document.getElementsByTagName();

        Exemplo:

        const paragrafos = document.getElementsByTagName("p");

        Resultado:

        HTMLCollection(3)

        Acessando elementos:

        console.log(paragrafos[0]);
        console.log(paragrafos[1]);
        console.log(paragrafos[2]);

        É exatamente igual à NodeList.

        Percorrendo uma HTMLCollection:

        Ela não possui forEach().

        O jeito mais comum é usar for...of:

        for (const p of paragrafos) {
            console.log(p);
        }

        Ou um for tradicional:

        for (let i = 0; i < paragrafos.length; i++) {
            console.log(paragrafos[i]);
        }

    Diferença mais importante: coleção "viva" (live) e "estática" (static)

    Essa é a principal diferença entre elas.

    HTMLCollection é "live"

        Ela acompanha automaticamente as alterações no DOM.

        Exemplo:

        <body>
            <p>Um</p>
            <p>Dois</p>
        </body>

        const paragrafos = document.getElementsByTagName("p");
        console.log(paragrafos.length); // 2
        const novo = document.createElement("p");
        novo.textContent = "Três";
        document.body.appendChild(novo);
        console.log(paragrafos.length); // 3

        A coleção foi atualizada automaticamente.

    NodeList é "estática"

        Ela representa uma "fotografia" do momento em que foi criada.

        const paragrafos = document.querySelectorAll("p");
        console.log(paragrafos.length); // 2
        const novo = document.createElement("p");
        novo.textContent = "Três";
        document.body.appendChild(novo);
        console.log(paragrafos.length); // continua 2

        Para obter a lista atualizada, é necessário fazer a seleção novamente:

        const paragrafosAtualizados = document.querySelectorAll("p");

    Convertendo para um Array

        Se você quiser usar métodos como map(), filter() ou reduce(), pode converter qualquer uma delas em um array.

        const lista = document.querySelectorAll("p");
        const array = Array.from(lista);
        console.log(array);

        Ou:

        const lista = document.getElementsByClassName("texto");
        const array = Array.from(lista);

    Qual usar?

        Hoje, em projetos modernos, a maioria dos desenvolvedores prefere:

        document.querySelector();
        document.querySelectorAll();

        Motivos:

        usam os mesmos seletores do CSS;
        são mais flexíveis;
        NodeList oferece o método forEach();
        a coleção estática evita comportamentos inesperados quando o DOM muda;

- O que são Web APIs

    As Web APIs são funcionalidades disponibilizadas pelo navegador para que o JavaScript possa interagir com a página, o computador do usuário e serviços da web.

    Uma dúvida muito comum é pensar que tudo faz parte do JavaScript. Na verdade, não faz.

    O JavaScript é apenas a linguagem. Quem fornece recursos como manipular o HTML, fazer requisições HTTP ou usar o GPS é o navegador, por meio das Web APIs.

    Quem faz o quê?

        Podemos imaginar a arquitetura assim:

        Seu código JavaScript
                │
                ▼
        Engine JavaScript (V8, SpiderMonkey...)
                │
                ▼
            Web APIs
                │
                ▼
            Navegador


        JavaScript executa seu código.
        Web APIs oferecem funcionalidades extras.
        Navegador implementa essas APIs.

        Exemplo: 

        console.log("Olá");

        console.log() não faz parte da linguagem JavaScript. Quem fornece o objeto console é o navegador (ou o ambiente de execução, como o Node.js).

        document.querySelector("h1");

        Também não faz parte do JavaScript. O objeto document pertence à DOM API, que é uma Web API.

    Principais Web APIs

        | API               | Para que serve?                                                          |
        | ------------------| ------------------------------------------------------------------------ |
        | DOM API           | Manipular HTML e CSS                                                     |
        | Events API        | Responder a cliques, teclado, mouse etc.                                 |
        | Fetch API         | Fazer requisições HTTP                                                   |
        | Timer API         | Executar código após um tempo ou em intervalos                           |
        | Local Storage API | Armazenar dados no navegador                                             |
        | Geolocation API   | Obter a localização do usuário                                           |
        | Clipboard API     | Copiar e ler texto da área de transferência                              |
        | Canvas API        | Desenhar gráficos e animações                                            |
        | Audio/Video API   | Controlar mídia                                                          |
        | BOM               | Acessar informações do navegador (`window`, `location`, `history`, etc.) |

    Serve para:

    Mostrar avisos
    Exibir mensagens simples
    Testar programas durante o desenvolvimento

    Sintaxe:

    alert(<mensagem>);

    Exemplo:

    alert("Bem-vindo ao jogo!");

- Funções matematicas com Math

    Math.random()

        É um método do objeto Math que gera um número aleatório.

        Sempre retorna um número entre 0 (inclusive) até 1 (exclusivo). Nunca retorna exatamente 1.

        Ou seja:

        0 <= número < 1

        Exemplos:

        0.12345
        0.98765
        0.00012

        Sintaxe:

        Math.random()

        Exemplo:

        const numero = Math.random();

    Math.trunc()

        Remove a parte decimal de um número. Não arredonda. Apenas corta.

        Sintaxe:

        Math.trunc(<valor>);

        Exemplo:

        Math.trunc(4.9)

        Resultado:

        4

- Gerar numeros inteiros aleatorios entre range de valores

    Utilizar a formula abaixo:

    Math.trunc(Math.random() * (max - min + 1)) + min;

    Exemplo:

    Gerando de 1 a 10

    const numero = Math.trunc(Math.random() * (10 - 1 + 1)) + 1;

    Gerando de 20 a 50

    const numero = Math.trunc(Math.random() * (50 - 20 + 1)) + 20;

- Adicionando eventos ao HTML

    É utilizado o método "addEventListener()" para isso, ele adiciona um evento a um elemento.

    É uma das funções mais importantes do JavaScript.

    Sintaxe:

    <elemento>.addEventListener(<evento>, <função>);

    Exemplo:

    const botao = document.querySelector(".btn");

    botao.addEventListener("click", function () {
        console.log("Clicou!");
    });

    Eventos comuns:

    Evento	    O que faz

    click	    Clique
    input	    Digitação
    change	    Mudança de valor
    submit	    Envio do formulário
    keydown	    Tecla pressionada
    keyup	    Tecla solta
    mouseover	Mouse entrou

    Voce pode inserir a funcao direto no evento ou criar uma função a parte e inserir sua declaração no evento, por exemplo:

    function clicou() {
        console.log("Clicou!");
    }

    const botao = document.querySelector(".btn");

    botao.addEventListener("click", clicou);

    Um ponto iportante é nao usar parenteses () pois a funcao nao deve ser chamda e sim passada ao evento.

- Parametro "e" em addEventListener

    Por exemplo o codigo abaixo:

    document.addEventListener("keydown", function (e) {
        console.log(e.key);
    });

    A função do addEventListener pode receber um parametro "e" e o que seria este parametro?

    O parâmetro "e" é um objeto criado automaticamente pelo navegador no momento em que o evento acontece.

    Ele é um objeto que contém várias informações sobre o evento que acabou de acontecer.

    O nome "e" é apenas um nome de variável mas é o padrao normalmente utilizado neste caso.

    Seu retorno neste caso é:

    ...
    key: "Enter"
    keyCode: 13
    charCode: 0
    code: "Enter"
    ctrlKey: false
    altKey: false
    metaKey: false
    ...

    A propriedade "key" informa a tecla pressionada.

    Dependendo do tipo de evento (clique de mouse por exemplo) estas informações podem ser diferentes.

- O que é JavaScript (de forma simples)

    "JavaScript é uma linguagem de programação de alto nível, orientada a objetos e multiparadigma."

    De forma simples:

    JavaScript é uma linguagem de alto nível (fácil para humanos escreverem), orientada a objetos (permite organizar o código em objetos) e multiparadigma (suporta diferentes estilos de programação, como procedural, orientação a objetos e funcional).

- O que é JavaScript (de forma complexa)

    "JavaScript é uma linguagem de programação de alto nível, orientada a objetos baseada em protótipos, multiparadigma, interpretada ou compilada Just-In-Time (JIT), tipagem dinâmica, de thread única, com coleta automática de lixo, que possui funções de primeira classe e um modelo de concorrência baseado em um loop de eventos não bloqueante."

    De forma detalhada:

    Alto nível:

        O JavaScript esconde os detalhes mais complexos do computador. Você escreve código pensando na lógica do programa, enquanto a linguagem cuida da memória e da comunicação com o sistema operacional.

    Orientada a objetos baseada em protótipos:

        Em vez de herdar comportamento apenas por meio de classes os objetos podem herdar diretamente de outros objetos através dos protótipos.

    Multiparadigma:

        O JavaScript não obriga você a programar de uma única forma.

        Você pode escrever código:

        Procedural
        Orientado a objetos
        Funcional

    Interpretada ou compilada JIT:

        Antigamente o JavaScript era apenas interpretado.

        Hoje, motores modernos como o V8 (Chrome e Node.js) compilam o código em linguagem de máquina durante a execução (Just-In-Time Compilation), tornando-o muito mais rápido.

        Você continua escrevendo JavaScript normalmente; essa otimização acontece "por baixo dos panos".

    Tipagem Dinâmica:

        O tipo das variáveis não precisa ser declarado.

        Além disso, uma variável pode mudar de tipo durante a execução.

        Tudo isso é permitido.

    Thread única:

        O JavaScript possui uma única thread principal de execução.

        Isso significa que ele executa uma instrução após a outra, em sequência.

        Apesar disso, ele consegue lidar com várias tarefas "ao mesmo tempo" graças ao Event Loop.

    Coleta automática de lixo:

        Quando um objeto não é mais utilizado, o JavaScript libera automaticamente a memória ocupada por ele.

        O programador normalmente não precisa se preocupar em liberar memória manualmente.

    Funções de primeira classe:

        As funções são tratadas como qualquer outro valor.

        Você pode:

        Guardar uma função em uma variável
        Passar uma função como parâmetro
        Retornar uma função de outra função

    Modelo de concorrência com Event Loop não bloqueante:

        Mesmo sendo single-threaded, o JavaScript não fica parado esperando operações demoradas.

        Enquanto essas operações acontecem, o JavaScript continua executando o restante do código e só volta para elas quando estiverem prontas.

        É isso que torna aplicações web e servidores em Node.js responsivos.

- O que é um JavaScript Runtime

    Um JavaScript Runtime é o ambiente completo onde o JavaScript é executado.

    Ele é composto pela JavaScript Engine mais várias ferramentas e recursos que permitem ao JavaScript fazer coisas úteis, como acessar o DOM, ler arquivos, fazer requisições de rede, usar temporizadores etc.

    Resumindo: a Engine executa o código; o Runtime fornece tudo o que o código precisa para funcionar.

    Exemplo do Runtime do navegador

        Quando o JavaScript roda no navegador, ele tem acesso a recursos como:

        Navegador (Runtime)
        │
        ├── JavaScript Engine
        ├── DOM
        ├── Web APIs
        ├── Event Loop
        └── Callback Queue

    O que cada parte faz?

        JavaScript Engine : Executa o código JavaScript.
        DOM : Permite modificar a página HTML.
        Web APIs : Recursos fornecidos pelo navegador, como fetch(), setTimeout(), geolocalização, áudio, vídeo etc.
        Event Loop : Coordena a execução de tarefas assíncronas.
        Callback Queue : Fila onde ficam funções aguardando sua vez de serem executadas.

- O que é um JavaScript Engine

    Uma JavaScript Engine (Motor JavaScript) é um programa responsável por ler, interpretar, otimizar e executar o código JavaScript.

    Ou seja, quando você escreve:

    console.log("Olá Mundo");

    Quem realmente executa esse código é a JavaScript Engine, e não o navegador diretamente.

    Pense nela como um tradutor entre o código JavaScript e o processador do computador.

    Imagine que você escreveu um livro em português.

    O processador do computador só entende uma linguagem muito simples (código de máquina).

    A JavaScript Engine é um tradutor que lê seu português e o converte para uma linguagem que o processador consegue executar.

    Seu código JavaScript
            │
            ▼
    JavaScript Engine
            │
            ▼
    Código de Máquina
            │
            ▼
    Processador

    Onde existe uma JavaScript Engine?

        Todo ambiente que executa JavaScript possui uma Engine.

        Alguns exemplos:

        | Ambiente        | Engine         |
        | --------------- | -------------- |
        | Google Chrome   | V8             |
        | Microsoft Edge  | V8             |
        | Node.js         | V8             |
        | Mozilla Firefox | SpiderMonkey   |
        | Safari          | JavaScriptCore |

        Cada uma faz a mesma coisa, mas possui implementações diferentes.

    Como ela funciona?

        De forma simplificada, o processo é este:

        Código JavaScript
            │
            ▼
        1. Parser
            │
            ▼
        2. AST (Árvore Sintática)
            │
            ▼
        3. Bytecode
            │
            ▼
        4. Interpretador
            │
            ▼
        5. Compilador JIT
            │
            ▼
        Código de Máquina
            │
            ▼
        Processador

        Vamos entender cada etapa.

        1. Parser

        O parser lê seu código e verifica se existe algum erro de sintaxe.

        2. AST (Abstract Syntax Tree)

        O código é transformado em uma árvore que representa sua estrutura.

        3. Bytecode

        A árvore é convertida para um código intermediário chamado bytecode. Ele é mais simples que JavaScript, mas ainda não é código de máquina.

        4. Interpretador

        O interpretador começa a executar o bytecode imediatamente. Isso faz os programas iniciarem rapidamente.

        5. Compilador JIT

        Enquanto o programa roda, a Engine observa quais partes do código são executadas muitas vezes. Essas partes são compiladas para código de máquina. Assim elas passam a executar muito mais rápido.

    A Engine faz apenas isso?

        Não.

        Ela também cuida de diversas outras tarefas importantes.

        Por exemplo:

        Gerenciamento de memória

        Quando você cria um objeto a engine reserva memória automaticamente.

        Garbage Collector

        Quando esse objeto não é mais utilizado a engine percebe que ninguém mais usa aquele objeto e libera a memória automaticamente.

        Otimizações

        Ela tenta descobrir formas de executar o código mais rapidamente.

        Por exemplo:

        Otimiza loops
        Otimiza funções chamadas muitas vezes
        Reutiliza memória
        Remove trabalho desnecessário

        Tudo isso acontece sem que o programador precise fazer nada.

    Diferença entre JavaScript Engine × Runtime

        Essa diferença costuma confundir quem está começando.

        JavaScript Engine é quem executa o código JavaScript.

        Runtime é o ambiente completo onde o JavaScript roda.

        Por exemplo:

        No navegador:

        Navegador
        │
        ├── DOM
        ├── Web APIs
        ├── Event Loop
        └── JavaScript Engine

        No Node.js:

        Node.js
        │
        ├── Sistema de arquivos
        ├── Rede
        ├── Event Loop
        └── V8 (Engine)

        A Engine é apenas uma parte do ambiente de execução (runtime).

- Como funciona atualmente a forma de interpretador / compilador JIT do JavaScript

    Atualmente, JavaScript não é apenas interpretado nem apenas compilado. Os motores modernos (como o V8 do Chrome e Node.js, SpiderMonkey do Firefox e JavaScriptCore do Safari) usam uma combinação de interpretação e compilação JIT (Just-In-Time).

    Vamos ver o processo de forma simples.

    Passo 1: Você escreve o código

        function soma(a, b) {
            return a + b;
        }

        console.log(soma(5, 3));

        Esse código é apenas texto.

    Passo 2: O motor lê o código (Parser)

        O primeiro passo é analisar o código para verificar se ele está correto.

        Por exemplo:

        let x = ;

        Aqui o parser detecta um erro de sintaxe antes mesmo do programa começar.

    Passo 3: É criada a AST (Abstract Syntax Tree)

        O código é transformado em uma estrutura em árvore.

        Não é exatamente assim, mas imagine algo parecido:

        Function
        ├── nome: soma
        ├── parâmetros
        │     ├── a
        │     └── b
        └── return
            └── +
                ├── a
                └── b

        Essa árvore facilita o entendimento do código pelo motor.

    Passo 4: Geração de Bytecode

        A AST é convertida para um bytecode.

        O bytecode é uma linguagem intermediária, muito mais simples para o computador entender do que o JavaScript, mas ainda não é código de máquina.

        É algo parecido com:

        Load a
        Load b
        Add
        Return

        Você nunca vê esse bytecode.

    Passo 5: O Interpretador executa o bytecode

        O interpretador começa a executar o programa imediatamente.

        Isso faz o JavaScript iniciar rapidamente, sem precisar compilar tudo antes.

    Passo 6: O motor observa o código

        Enquanto o programa roda, o motor coleta informações como:

        Quais funções são chamadas muitas vezes
        Quais tipos de dados aparecem
        Quais partes do código são mais utilizadas

        Exemplo:

        for (let i = 0; i < 1000000; i++) {
            soma(i, i);
        }

        A função soma() será chamada um milhão de vezes.

        O motor percebe que vale a pena otimizá-la.

    Passo 7: Entra o compilador JIT

        Nesse momento, o compilador Just-In-Time converte essa função diretamente em código de máquina do processador.

        Depois disso, ela passa a executar muito mais rapidamente.

        Passo 8: Se necessário, ele desfaz a otimização

        Imagine que durante muito tempo a função recebeu apenas números:

        soma(5, 8)

        O compilador otimiza pensando nisso.

        Depois aparece:

        soma("5", "8")

        Agora a função está trabalhando com strings.

        A otimização anterior pode não servir mais.

        O motor então faz uma desotimização (deoptimization) e gera uma nova versão mais adequada.

        Isso acontece automaticamente.

    Fluxo resumido:

        Código JavaScript
                │
                ▼
            Parser
                │
                ▼
            AST
                │
                ▼
            Bytecode
                │
                ▼
        Interpretador
                │
                ▼
        Monitora o desempenho
                │
                ▼
        Compilador JIT
                │
                ▼
        Código de máquina otimizado

    E por que não compilar tudo logo no início?

    Porque isso faria a inicialização demorar mais.

    Imagine um site com 500 mil linhas de JavaScript.

    Talvez apenas 10% do código seja realmente usado quando a página abre.

    Compilar tudo antes seria desperdício.

    O JIT compila apenas as partes "quentes" (hot code), ou seja, as que são executadas repetidamente.

- O que é Execution Context

    Um Execution Context (Contexto de Execução) é uma estrutura interna criada pelo motor JavaScript sempre que um trecho de código precisa ser executado.

    Ele contém todas as informações necessárias para que aquele código possa ser executado corretamente.

    Essas informações incluem:

        As variáveis declaradas naquele contexto.
        As funções declaradas naquele contexto.
        Os parâmetros recebidos (quando for uma função).
        O valor de "this".
        A referência ao contexto externo (escopo léxico), que permite acessar variáveis de contextos superiores.

    É importante entender que o Execution Context não é algo que você cria manualmente. Ele é criado automaticamente pela JavaScript Engine.

    Quais tipos de Execution Context existem?

        Na prática, para quem está começando, existem dois principais:

        Global Execution Context
        Function Execution Context

    O que é o Global Execution Context?

        O Global Execution Context é o primeiro contexto criado quando um programa JavaScript começa a ser executado.

        Existe apenas um Global Execution Context durante a execução de um script.

        Considere este código:

        let nome = "Fernando";

        function saudacao() {
            console.log("Olá");
        }

        const idade = 47;

        Antes mesmo da primeira linha ser executada, o motor JavaScript cria o Global Execution Context.

        É nele que ficam registradas todas as declarações feitas fora de funções.

        Nesse exemplo, o contexto global conterá informações como:

        Global Execution Context

        Variáveis:
        nome
        idade

        Funções:
        saudacao()

        Quando a execução chega ao final do arquivo, esse contexto continua existindo enquanto o programa estiver em execução.

        No navegador, por exemplo, ele permanece enquanto a página estiver aberta.

    O contexto global representa todo o arquivo?

        Em um script simples, sim.

        Todo código que está fora de funções pertence ao contexto global.

        Exemplo:

        let x = 10;

        console.log(x);

        function teste() {
        }

        As três instruções acima pertencem ao contexto global.

    O que acontece quando uma função é chamada?

        Quando uma função é executada, o JavaScript cria um novo Execution Context exclusivamente para ela.

        Exemplo:

        function soma(a, b) {
            let resultado = a + b;
            return resultado;
        }

        soma(5, 8);

        Quando soma(5, 8) é chamada, é criado um novo contexto contendo:

        Function Execution Context

        Parâmetros:
        a = 5
        b = 8

        Variáveis:
        resultado

        this

        Escopo externo

        Esse contexto existe apenas durante a execução da função.

        Quando ela termina, ele é removido.

    Por que criar um novo contexto para cada função?

        Porque cada chamada da função pode ter valores diferentes.

        Veja:

        function soma(a, b) {
            return a + b;
        }

        soma(2, 3);
        soma(10, 20);

        Cada chamada possui seus próprios valores de "a" e "b".

        A primeira chamada cria um contexto semelhante a:

        a = 2
        b = 3

        A segunda cria outro:

        a = 10
        b = 20

        Os dois contextos são independentes.

    O que existe dentro de um Execution Context?

        Podemos dividir em algumas partes principais.

        Variáveis

            let nome = "Fernando";

            O contexto sabe que existe uma variável chamada `nome`.

        Funções

            function calcular() {
            }

            O contexto registra que existe uma função chamada `calcular`.

        Parâmetros

            function soma(a, b) {
            }

            Quando a função é chamada:

            soma(5, 10);

            o contexto armazena:

            a = 5
            b = 10

        this

            Todo contexto possui um valor para this.

            O significado de this depende da forma como a função foi chamada.

        Referência ao contexto externo (escopo léxico)

            Esse é um dos pontos mais importantes.

            Veja:

            let nome = "Fernando";

            function mostrar() {
                console.log(nome);
            }

            mostrar();

            Dentro de mostrar() não existe nenhuma variável chamada nome.

            Mesmo assim o código funciona.

            Por quê?

            Porque o contexto da função possui uma referência ao contexto onde ela foi criada.

            Assim, quando não encontra nome localmente, o JavaScript procura no contexto externo.

    Qual o ciclo de vida de um Execution Context?

        Todo contexto passa por duas etapas principais.

        Fase de criação (Creation Phase)

            Primeiro o JavaScript prepara o contexto.

            Nessa fase ele:

            Registra as funções
            Registra as variáveis
            Cria espaço para elas
            Define o valor de this
            Estabelece o escopo externo

            Ainda não executa as instruções.

        Fase de execução (Execution Phase)

            Agora as instruções começam a ser executadas.

            Exemplo:

            let x = 10;

            console.log(x);

            É nessa fase que:

            x recebe o valor 10
            console.log() é executado

    O que acontece quando uma função chama outra?

        Considere:

        function A() {
            B();
        }

        function B() {
            C();
        }

        function C() {
            console.log("Fim");
        }

        A();

        A sequência é:

        1. Existe o contexto global.
        2. A() é chamada e cria um novo contexto.
        3. Dentro de A(), chama B() e cria outro contexto.
        4. Dentro de B(), chama C() e cria outro contexto.
        5. C() termina e seu contexto é removido.
        6. B() continua e termina e seu contexto é removido.
        7. A() termina e seu contexto é removido.
        8. Resta apenas o contexto global.

        Essa sequência será organizada pela Call Stack.

- O que é Call Stack

    O JavaScript cria um Execution Context para executar o código. Agora surge a pergunta:

    Se existem vários Execution Contexts, como o JavaScript sabe qual deve executar primeiro?

    A resposta é: Call Stack.

    O que é a Call Stack?

        A Call Stack (Pilha de Chamadas) é uma estrutura de dados utilizada pela JavaScript Engine para organizar e controlar a execução dos Execution Contexts.

        Ela determina qual código está sendo executado no momento e para qual código o JavaScript deve voltar quando uma função termina.

        É importante entender que a Call Stack não executa o código. Quem executa é a JavaScript Engine. A Call Stack apenas organiza a ordem em que os Execution Contexts são executados.

    Por que ela se chama "Stack" (Pilha)?

        Porque ela utiliza a estrutura de dados chamada pilha (Stack), que segue a regra LIFO (Last In, First Out):

        O último elemento que entra é o primeiro que sai.

        Imagine a seguinte sequência:

        Entrou A
        Entrou B
        Entrou C

        A saída obrigatoriamente será:

        Sai C
        Sai B
        Sai A

        A Call Stack funciona exatamente dessa maneira.

    Como a Call Stack começa?

        Considere este código:

        let nome = "Fernando";

        function saudacao() {
            console.log("Olá");
        }

        Quando o programa começa, a JavaScript Engine cria o Global Execution Context.

        Esse contexto é colocado na Call Stack.

        Neste momento temos:

        Call Stack

        ┌─────────────────────────┐
        │ Global Execution Context│
        └─────────────────────────┘

        Enquanto o programa estiver executando, sempre existirá pelo menos o contexto global na pilha.

    O que acontece quando uma função é chamada?

        Agora veja:

        function saudacao() {
            console.log("Olá");
        }

        saudacao();

        Inicialmente:

        Call Stack

        ┌─────────────────────────┐
        │ Global Execution Context│
        └─────────────────────────┘

        Quando a linha

        saudacao();

        é executada, o JavaScript cria um novo Function Execution Context.

        Esse contexto é colocado no topo da pilha.

        Agora temos:

        Call Stack

        ┌─────────────────────────┐
        │ saudacao()              │ ← sendo executado
        ├─────────────────────────┤
        │ Global Execution Context│
        └─────────────────────────┘

        Observe que o contexto global continua existindo.

        Ele apenas fica aguardando enquanto a função é executada.

    O que acontece quando a função termina?

        Depois que a função termina:

        console.log("Olá");

        seu contexto não é mais necessário.

        Ele é removido da Call Stack.

        Voltamos para:

        Call Stack

        ┌─────────────────────────┐
        │ Global Execution Context│
        └─────────────────────────┘

        A execução continua exatamente do ponto onde a função foi chamada.

    Exemplo com várias funções

        Considere:

        function A() {
            B();
        }

        function B() {
            C();
        }

        function C() {
            console.log("Fim");
        }

        A();

        Vamos acompanhar a pilha.

        Início:

            Call Stack

            ┌─────────────────────────┐
            │ Global                  │
            └─────────────────────────┘

        Chamada de A():

            Call Stack

            ┌─────────────────────────┐
            │ A                       │
            ├─────────────────────────┤
            │ Global                  │
            └─────────────────────────┘

        Dentro de A() é chamada B():

            Call Stack

            ┌─────────────────────────┐
            │ B                       │
            ├─────────────────────────┤
            │ A                       │
            ├─────────────────────────┤
            │ Global                  │
            └─────────────────────────┘

        Dentro de B() é chamada C():

            Call Stack

            ┌─────────────────────────┐
            │ C                       │ ← executando
            ├─────────────────────────┤
            │ B                       │
            ├─────────────────────────┤
            │ A                       │
            ├─────────────────────────┤
            │ Global                  │
            └─────────────────────────┘

        C termina:

            Call Stack

            ┌─────────────────────────┐
            │ B                       │
            ├─────────────────────────┤
            │ A                       │
            ├─────────────────────────┤
            │ Global                  │
            └─────────────────────────┘

        B termina:

            Call Stack

            ┌─────────────────────────┐
            │ A                       │
            ├─────────────────────────┤
            │ Global                  │
            └─────────────────────────┘

        A termina:

            Call Stack

            ┌─────────────────────────┐
            │ Global                  │
            └─────────────────────────┘

        Esse comportamento acontece milhares de vezes por segundo.

        Apenas o topo da pilha executa

        Uma característica muito importante é:

        A JavaScript Engine executa apenas o Execution Context que está no topo da Call Stack.

        Enquanto uma função estiver sendo executada, todas as funções abaixo dela ficam aguardando.

        Por isso o JavaScript é considerado single-threaded: existe apenas uma Call Stack principal executando código.

    O que acontece se uma função demora muito?

        Veja:

        function calcular() {
            // operação muito demorada
        }

        calcular();

        console.log("Fim");

        Enquanto calcular() estiver na Call Stack, o JavaScript não pode executar:

        console.log("Fim");

        Primeiro calcular() precisa terminar.

        Só então ela será removida da pilha.

        Depois disso, a execução continua.

    O que é um Stack Overflow?

        Talvez você já tenha visto o erro:

        Maximum call stack size exceeded

        Isso acontece quando a Call Stack fica grande demais.

        O caso mais comum é uma recursão infinita:

        function repetir() {
            repetir();
        }

        repetir();

        O que acontece?

        A Call Stack fica assim:

        Global
        repetir()
        repetir()
        repetir()
        repetir()
        repetir()
        ...

        Como nenhuma chamada termina, novos Execution Contexts continuam sendo empilhados.

        Em algum momento o limite de memória da pilha é atingido.

        Então o JavaScript interrompe o programa com o erro:

        Maximum call stack size exceeded

    Relação entre Execution Context e Call Stack

        Agora podemos juntar os dois conceitos.

        O Execution Context é o ambiente criado para executar um trecho de código.

        A Call Stack é a estrutura que organiza esses ambientes.

        Ou seja:

        A JavaScript Engine cria um Execution Context.
        Esse contexto é colocado na Call Stack.
        O contexto que está no topo da pilha é executado.
        Quando termina, é removido.
        A execução continua no contexto anterior.

        Sem a Call Stack, a Engine não saberia qual função executar nem para qual função retornar após o término de outra.

- O que é Callback Queue

    Sabemos que o JavaScript é single-threaded, ou seja, ele possui apenas uma Call Stack.

    Imagine este código:

    console.log("Início");

    // operação que demora 5 segundos

    console.log("Fim");

    Se essa operação demorasse 5 segundos e o JavaScript ficasse esperando, durante esses 5 segundos absolutamente nada mais poderia ser executado.

    A página travaria.

    O navegador deixaria de responder.

    Para resolver esse problema existe o Runtime, que possui alguns componentes importantes:

    Runtime

    ├── JavaScript Engine
    ├── Call Stack
    ├── Web APIs
    ├── Callback Queue
    └── Event Loop

    O que é a Callback Queue?

        A Callback Queue (Fila de Callbacks) é uma fila onde ficam armazenadas funções que já estão prontas para serem executadas, mas ainda não podem entrar na Call Stack.

        Essa definição é extremamente importante.

        Ela não executa nada.

        Ela apenas espera.

    O que é um callback?

        Antes de continuar, precisamos entender a palavra callback.

        Um callback é simplesmente uma função que será executada mais tarde.

        Exemplo:

        function mostrarMensagem() {
            console.log("Olá");
        }

        Essa é apenas uma função.

        Agora:

        setTimeout(mostrarMensagem, 3000);

        Aqui estamos dizendo:

        Daqui a 3 segundos execute mostrarMensagem.

        Nesse momento mostrarMensagem passa a ser um callback.

        Ela será chamada futuramente.

    O caminho de um callback

        Veja este código:

        console.log("A");

        setTimeout(function () {
            console.log("B");
        }, 3000);

        console.log("C");

        Vamos acompanhar passo a passo.

        Passo 1:

            O programa começa.

            A Call Stack contém apenas o contexto global.

            Call Stack

            ┌───────────────┐
            │ Global        │
            └───────────────┘

        Passo 2:

            Executa:

            console.log("A");

            Resultado:

            A

        Passo 3:

            Agora encontra:

            setTimeout(...)

            Muita gente acha que o JavaScript espera 3 segundos.

            Não espera.

            O que acontece é:

            A JavaScript Engine entrega essa tarefa para uma Web API do navegador.

            A Web API passa a contar os 3 segundos.

            Enquanto isso, a Call Stack continua livre.

        Passo 4:

            O JavaScript continua normalmente.

            Executa:

            console.log("C");

            Resultado:

            A
            C

            Observe que os 3 segundos ainda nem terminaram.

        Passo 5:

            Depois de 3 segundos...

            A Web API termina seu trabalho.

            Ela não coloca a função diretamente na Call Stack.

            Ela coloca na Callback Queue.

            Agora temos:

            Callback Queue

            ┌──────────────────────┐
            │ console.log("B")     │
            └──────────────────────┘

            A função está pronta.

            Mas ainda não está sendo executada.

    Por que ela não vai direto para a Call Stack?

        Porque talvez a Call Stack esteja ocupada.

        Imagine:

        function calculoGigante() {
            // demora vários segundos
        }

        Enquanto essa função estiver executando:

        Call Stack

        ┌───────────────┐
        │ calculoGigante│
        ├───────────────┤
        │ Global        │
        └───────────────┘

        Não é possível colocar outra função na pilha.

        A regra da Call Stack é:

        Apenas um Execution Context pode ser executado por vez.

        Então o callback precisa esperar.

        É exatamente para isso que existe a Callback Queue.

        Ela funciona como uma fila

        A Callback Queue segue a regra FIFO (First In, First Out).

        Quem chega primeiro é executado primeiro.

        Imagine:

        setTimeout(A, 1000);

        setTimeout(B, 1000);

        setTimeout(C, 1000);

        Depois de um segundo:

        Callback Queue

        ┌───────┐
        │ A     │
        ├───────┤
        │ B     │
        ├───────┤
        │ C     │
        └───────┘

        A ordem será:

        A
        B
        C

    A Callback Queue executa alguma coisa?

        Não.

        Esse é um erro muito comum.

        A Callback Queue:

        Não executa funções
        Não cria Execution Contexts
        Não coloca funções na Call Stack

        Ela apenas armazena callbacks que já estão prontos.

    Então quem tira da fila?

        Esse é justamente o trabalho do Event Loop.

        Ele fica verificando continuamente:

        A Call Stack está vazia?
        Existe alguma função esperando na Callback Queue?

        Se a resposta for "sim", ele move a primeira função da fila para a Call Stack.

    Um detalhe importante

    A Callback Queue não serve apenas para `setTimeout().

    Várias operações assíncronas utilizam esse mecanismo (ou mecanismos muito parecidos), por exemplo:

    Eventos de clique (click)
    Teclado (keydown)
    Mouse (mousemove)
    Mensagens de rede
    Algumas operações do Node.js

    Sempre que uma operação termina e precisa executar um callback, ele normalmente passa primeiro pela fila apropriada.

- O que é Event Loop

    O Event Loop é um componente do JavaScript Runtime responsável por monitorar continuamente a Call Stack e as filas de tarefas (como a Callback Queue) para decidir quando um callback pode voltar a ser executado.

    Ele não executa o código.

    Quem executa o código continua sendo a JavaScript Engine.

    O Event Loop apenas coordena quando uma função pode voltar para a Call Stack.

    Por que o Event Loop existe?

        Lembre-se de uma característica importante do JavaScript:

        Existe apenas uma Call Stack principal.

        Isso significa que apenas uma função pode estar sendo executada por vez.

        Agora imagine este código:

        console.log("A");

        setTimeout(() => {
            console.log("B");
        }, 1000);

        console.log("C");

        O resultado é:

        A
        C
        B

        Mas por quê?

        É exatamente isso que o Event Loop torna possível.

    O funcionamento completo

        Vamos acompanhar tudo o que acontece.

        Passo 1 — O programa começa

            O Runtime cria o Global Execution Context.

            A Call Stack fica assim:

            Call Stack

            ┌────────────────────┐
            │ Global             │
            └────────────────────┘

        Passo 2 — Executa console.log("A")

            A Engine executa normalmente.

            Resultado:

            A

        Passo 3 — Encontra setTimeout

            setTimeout(() => {
                console.log("B");
            }, 1000);

            Aqui acontece algo importante.

            O JavaScript não espera um segundo.

            Em vez disso:

            1. A Engine encontra setTimeout().
            2. O Runtime envia essa tarefa para uma Web API.
            3. A Web API começa a contar 1 segundo.
            4. A Engine continua executando o restante do código.

            A Call Stack não fica bloqueada.

        Passo 4 — Executa console.log("C")

            Resultado:

            A
            C

            Neste momento, a Call Stack termina sua execução.

            Fica apenas o contexto global.

        Passo 5 — O temporizador termina

            Depois de um segundo, a Web API termina seu trabalho.

            Ela coloca o callback na Callback Queue.

            Callback Queue

            ┌────────────────────┐
            │ console.log("B")   │
            └────────────────────┘

            Ainda não aconteceu nenhuma execução.

            A função apenas está esperando.

        Passo 6 — O Event Loop entra em ação

        O Event Loop verifica continuamente duas coisas:

        1. A Call Stack está vazia?
        2. Existe algum callback esperando?

        Neste momento:

        Call Stack

        (vazia)

        Callback Queue

        ┌────────────────────┐
        │ console.log("B")   │
        └────────────────────┘

        Como ambas as condições foram satisfeitas, o Event Loop move o callback para a Call Stack.

        Agora temos:

        Call Stack

        ┌────────────────────┐
        │ callback           │
        └────────────────────┘

        Agora sim a Engine pode executar a função.

        Resultado:

        B

    O Event Loop faz isso uma única vez?

        Não.

        Ele faz isso continuamente.

        Durante toda a execução do programa ele fica verificando:

        Call Stack está livre?

        ↓

        SIM

        ↓

        Existe callback esperando?

        ↓

        SIM

        ↓

        Move callback para a Call Stack

        ↓

        Repete tudo novamente

        Esse ciclo acontece milhares de vezes por segundo.

    O Event Loop nunca interrompe uma função

        Esse é um detalhe muito importante.

        Imagine:

        function calculo() {
            // demora 10 segundos
        }

        Enquanto calculo() estiver executando:

        Call Stack

        ┌──────────────────┐
        │ calculo()        │
        ├──────────────────┤
        │ Global           │
        └──────────────────┘

        Mesmo que existam 50 callbacks esperando:

        Callback Queue

        A
        B
        C
        D
        E
        ...

        O Event Loop não pode interromper calculo().

        Ele apenas espera.

        Somente quando calculo() terminar é que poderá mover o primeiro callback.

        Esse comportamento garante que uma função nunca seja interrompida no meio da execução.

    O Event Loop executa callbacks?

        Não.

        Esse é outro erro bastante comum.

        O Event Loop apenas faz isto:

        Callback Queue
            │
            ▼
        Call Stack

        Quem executa o callback continua sendo a JavaScript Engine.

    Por que isso torna o JavaScript "assíncrono"?

        Na verdade, a linguagem JavaScript continua sendo single-threaded.

        Quem faz o trabalho assíncrono são as Web APIs (no navegador) ou as APIs do Node.js.

        O Event Loop apenas coordena quando essas operações terminadas podem voltar para a execução normal.

        Por isso costuma-se dizer:

        O JavaScript não é assíncrono por si só.

        O Runtime é que fornece esse comportamento.

    Fluxo completo

        Agora podemos montar todo o caminho que uma operação assíncrona percorre.

        Código JavaScript
                │
                ▼
        JavaScript Engine
                │
                ▼
        Call Stack
                │
                ▼
        Operação assíncrona
        (setTimeout, click, rede...)
                │
                ▼
        Web API / Node API
                │
                ▼
        Callback Queue
                │
                ▼
        Event Loop
                │
                ▼
        Call Stack
                │
                ▼
        JavaScript Engine executa o callback

        Essa figura resume praticamente todo o funcionamento do JavaScript assíncrono.

    Uma observação importante

        Para simplificar, durante toda a explicação falamos apenas da Callback Queue.

        Na realidade, os motores modernos possuem mais de uma fila de tarefas.

        Por exemplo:

        Microtask Queue (usada por Promise, queueMicrotask, MutationObserver).
        Task Queue ou Macrotask Queue (usada por `setTimeout`, eventos de clique, etc.).

        O Event Loop possui regras de prioridade entre essas filas.
